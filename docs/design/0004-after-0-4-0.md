# Design 0004: follow-ups after 0.4.0

- Status: Accepted, 2026-11-02
- Target release: 0.5.0
- Created: 2026-11-02
- Decision record: none

The owner settled these on 2026-11-02 after installing and checking 0.4.0.
S5 and S6 were settled the same day.

## Owner decisions (2026-11-02)

| | Question | Answer |
|---|---|---|
| S1 | Nested runs are listed oldest first by start time, but each row shows its end time, so the times read out of order | Nested rows show their start time. |
| S2 | A flow with many runs makes the three-item Finished preview long | In Finished, a parent's nested runs are hidden until the parent is expanded. |
| S3 | After an upgrade, opening Ember from the dock brings up the old version still running | Ember offers a restart. |
| S4 | Check now on Engines has a label only; on Dependencies it also has an icon | Both have the icon. |
| S5 | The update notice reads the latest release from GitHub without signing in; the repository is private, so GitHub answers 404 and the notice never shows | Ember drops the update notice. |
| S6 | A pull request's merge commit carries its title in the body, and Release Please lists that title as an extra change | Pull requests merge with an empty body. |

## Design

T1. Start time on nested rows. A run row nested under a flow or panel
shows `Started <time> · <duration>`, the time in the same format as other
rows (`Today 16:56`). A finished nested run's duration is its run time; a
live one's is its elapsed time. Top-level rows keep their current time
text. The order stays oldest first by start time, then by run id (design
0003, R3).

T2. Collapsed nested runs in Finished. In Finished, both in the preview and
in the full list, a flow's or panel's nested runs are hidden until the
parent's details are expanded. The parent's second line names how many
runs it holds: `1 run` or `<n> runs`. A Finished parent with a live nested
run, such as a writer turn still running under a cancelled flow, keeps its
nested runs shown, as Live does (settled by the owner on 2026-11-02 during
the build). Expanding the parent shows its
details and its nested runs; collapsing hides both. Live keeps every
nested run shown, as now. Clear, the filters and the record of which runs
are nested do not change.

T3. Restart after an upgrade. When `emb app` hands over to an Ember that is
already running, the running Ember compares its own version with the
installed one. When they differ, its window shows an info alert, "Ember
<installed version> is installed. Restart to use it.", with a Restart
button. Restart quits the running Ember and starts the installed one, which
opens its window. Runs keep running in their tmux sessions; an open screen
mirror closes. The alert stays until Ember restarts.

T4. Check now icon. The Check now button in the Engines screen's header
shows the `refresh-cw` icon in `text-primary` before its label, as the
Dependencies screen's Check now does, and keeps the accessible name "Check
now". The icon follows the theme.

T5. No update notice. The Dependencies screen and `emb deps` no longer read
or show the latest Ember release; the `ember_release` field leaves the
`emb deps --json` report and the cache. Design 0002's D4 no longer applies.

T6. Merging pull requests. A pull request merges with a merge commit whose
subject is GitHub's default and whose body is empty:
`gh pr merge <n> --merge --body ""`. `docs/releasing.md` states the rule.
