# Design 0003: display fixes and additions after 0.3.0

- Status: Accepted, 2026-11-02
- Target release: 0.4.0
- Created: 2026-11-02
- Decision record: none

The owner reported these after installing 0.3.0 on 2026-11-02 and settled
each one the same day. The Ember design system artifact carries the same
rules for the app's look.

## Owner decisions (2026-11-02)

| | Question | Answer |
|---|---|---|
| Q1 | A clicked control keeps a blue focus ring | The ring shows only when focus arrives from the keyboard. |
| Q2 | Overview rows do not line up, the expand arrow does not look like a button, long detail lines wrap | Fixed columns, a bordered expand button, one-line title and detail. |
| Q3 | Nested runs under a flow or panel are in no time order | Oldest first by start time, then by id. |
| Q4 | Finished's pickers look like buttons | Every picker shows a chevron-down. |
| Q5 | Rounded borders show dots at 0°, 45° and 90° | Border colors are solid. |
| Q6 | A Menu control for flow review rounds | "Flow review rounds" on Menu, 1 to 4 reviews per task. |
| Q7 | Finished takes as much room as Live | Live leads; Finished shows its three newest items and Show all. |
| Q8 | Clear does not say what it does | A red outline button with the caption "Remove shown records". |
| Q9 | Status chips have square corners | 6px corners. |
| Q10 | The app icon's brown tile, and the icon looks smaller than its neighbours in the dock | A neutral charcoal tile that fills more of the icon. |

## Design

R1. Keyboard focus. A control shows the `focus-ring` outline only when it
took focus by Tab, Shift+Tab, a keyboard shortcut or a mnemonic. Focus
taken by a mouse click, or set by the app, shows no ring. A click shows the
control's own pressed, selected or open state. Every control stays
reachable with Tab, in reading order, with a visible ring (design 0001).

R2. Overview rows. Every run, flow and panel row in Live and Finished has
the same columns, each a fixed width: the expand button, the type marker,
the status chip, the text, and the time and actions on the right. A wider
type word or chip text never moves the next column. The expand button is a
32px round button with a `border-strong` outline and a chevron. The text
column has a title line and a detail line, each on one line and cut with an
ellipsis when too long; the full text is in the expanded details. A flow or
panel with a question adds a third such line. Nested rows are indented one
column.

R3. Nested run order. A flow's or panel's nested runs are listed oldest
first by start time, then by run id, in Live and Finished.

R4. Pickers. Every `QComboBox` shows a chevron-down at its right end, in
`text-secondary`, in both themes, from the app's Lucide `chevron-down` icon.

R5. Borders. `border` and `border-strong` are solid colors: light
`#e6e6e6` and `#cccccc`, dark `#414141` and `#4c4c4c`. No rounded border
uses a color with transparency.

R6. Flow review rounds. Menu's "Work of several tasks" card has a "Flow
review rounds" row below Multi-task work: a segmented control of 1, 2, 3
and 4, the most times a reviewer checks one flow task. It is the choices
row `flow.review_rounds`, values `1` to `4`, default `3`, saved at once and
settable with `emb choices --set` and `--once` like the other rows. A
plan's `rounds` (fix rounds, 0 to 3) wins when the plan sets it; otherwise
a flow uses the row's value minus one. `emb flow --dry-run` names the
rounds and where they came from.

R7. Overview layout. Live comes first and takes the room it needs.
Finished then shows a preview: its three newest top-level items, each with
its nested runs, and a "Show all <n>" button. The Type, Status and Engine
pickers and Clear show only when Finished is open. Show all opens the full
list (at most twenty top-level items); "Show fewer" returns to the preview.
The app remembers whether Finished was left open.

R8. Clear. Clear is a red outline button: a trash icon and "Clear" in
`danger-text`, a 1px `danger-text` outline, no fill, `danger-bg` on hover.
The caption "Remove shown records" sits under it in 12px
`text-secondary`. Its confirmation and what it removes do not change.

R9. Status chips. Chips have 6px corners in both themes, visible at every
display scale.

R10. App icon. The tile is `#262626` with a `#3a3a3a` edge, and spans 4 to
124 of the icon's 128 units. The coals grow with the tile; the top coal
stays `#f76707`. The small icon (16 to 32 pixels) and the design system's
logo files change the same way. The tray icons do not change.

## Build order

The lead builds every item with no worker, at the owner's choice: R4, R5
and R9 in `src/ember/app/theme.py`, then R1, then R2, R3, R7 and R8 in
`src/ember/app/screens/overview.py`, then R6 and R10.
