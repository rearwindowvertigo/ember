settled on 2026-11-02 after the 0.2.0 build: four fixes for 0.2.1, the
additions for 0.3.0, and the items that are not planned.

## A. 0.2.1 fixes

Target release: 0.2.1.

A1. The Codex driver reads "Selected model is at capacity" in a turn's
output as a provider error: the turn ends with exit 73 and the run's
`next:` line, as other provider errors do.

A2. When a flow writer's turn is collected but its commit is refused by a
hook (exit 77), a `--send` answer for that task delivers the hook's error
output to the writer together with the correction file, and the turn that
follows commits the writer's fixed files. The skill's flow reference
describes this case.

A3. Overview's flow line shows the plan wave of the latest active task as
`wave <n> of <m>`. The runner's pass count appears only in the flow's
expanded details, labelled as passes.

A4. `AppContext` saves take a result callback per save, called once with
success or the save's error. The Menu's Panel card unlocks from its own
save's callback and refreshes after its own save's failure; it reads no
queue internals or message text.

A5. Every skill eval case runs once after these fixes, before the 0.2.1
release pull request merges (P12).

## B. Flows

Target release: 0.3.0.

B1. `emb flow --cancel <flow> [--reason <text>]` stops the flow's runner,
closes no task run with `--force`, keeps every task branch and the flow
branch, records the flow as `cancelled` with the reason, and prints each
kept branch. A cancelled flow can be resumed with `--resume`.

B2. The skill lets Claude cancel a flow for any reason it states, and has
Claude report the cancel to the owner with the reason and every kept
branch.

## C. Panels

Target release: 0.3.0.

C1. `emb panel --retry <panel> <member>` starts one new read-only run for
a member whose outcome is failed, stalled, timed out or interrupted, and
adds its answer to `summary.md` and the panel record.

C2. `emb panel --close <panel>` closes every member run that is still open,
without `--force`, and reports each close and each refusal.

## D. Desktop app

Target release: 0.3.0.

D1. The tray's live state and its menu include running flows and panels.

D2. The Overview sidebar count includes flows and panels waiting for the
lead.

D3. The Flows and Panels cards have buttons that open `summary.md`, a
flow's briefs and its check logs in the desktop's default viewer.

D4. The Dependencies screen shows when a newer Ember release exists on
GitHub, with its version and download link. Ember does not install it.

D5. `emb deps` and the Dependencies screen list the `ember` skill link as a
component: current when `emb skill status` reports `installed`, and
otherwise its state with `emb skill install` (or `emb skill install
--force` for another link) as the command.

## E. Records

Target release: 0.3.0.

E1. `emb prune --older-than <days> [--dry-run] [--json]` removes ended run,
flow and panel records and their logs older than the given age. It deletes
no branch: unmerged task, flow and run branches are listed with the command
that removes each.

## Not planned

- A writer or reviewer per task in a flow plan (P6).
- Claude subagent panel members, and per-member spend in the panel summary
  (P7).
- An arm64 package and an apt repository (P10).
- Skill evals in `make check` or CI (P11).

## Build order

1. 0.2.1: A1 to A4 as one build step, then A5, then the release.
2. 0.3.0: B, C, D and E, planned and built after 0.2.1 is released.
