## Lead checks

- R3, R4: at tag `v0.2.1`, `CLAIM_TTL` is 7 days
  (`src/ember/choices.py:34`) and `finish` writes `gone` for every claim
  (`src/ember/choices.py:819`). The `gone` replies were normal finish
  results, not expiries. The 0.2.1 `skill/references/claims.md:43`
  already gave the 7-day lifetime. #45 (c2e8111, 0.6.0) added `was` to
  the reply, so R5 is `done`. A claim older than 7 days and a finished
  claim both still read `was: gone`, as terra and sol say.
- R16: a Codex worker started by `emb run` on 0.12.0
  (`codex-20261104-042316-b7c3de`, worktree
  `.ember/worktrees/codex-20261104-042316-b7c3de`) ran three `uv`
  commands. Each exited 2 with `failed to open file
  <main checkout>/pyproject.toml: Permission denied (os error 13)`:
  `uv run --frozen python`, `uv run --frozen ruff --version` and
  `uv run --no-project python`. Every `emb run` worktree sits under the
  main checkout, whose `pyproject.toml` the sandbox denies
  (`src/ember/sandbox.py:221`). The failure applies to every editing
  run, not only runs based on a flow worktree, and `--no-project` does
  not avoid it. No GitHub issue covers it.
- R7, R10: `skill/references/gap-check.md:56-61` requires coverage of
  every plan step. A task-scoped check changes that contract, which is
  haiku's and sonnet's reason for `owner`. No decision record rules it
  out. Five members propose it as a change.
- R33: `skill/SKILL.md:157-158` says "Never run two workers on the same
  file at once". Section scopes would change that rule, so the outcome is
  `owner`.
- R15: `docs/design/0002-after-0-2-0.md` P1 settled exit 73 for provider
  errors. No design or decision covers an automatic resend.
